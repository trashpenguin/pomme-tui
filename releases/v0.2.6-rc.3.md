# Pomme TUI 0.2.6-rc.3 — Repeat key correction

Fixes the confusing repeat/reload letter binding in the player.

- **r or R:** cycle repeat. Shift or Caps Lock no longer reloads the engine.
- **F5:** reload the audio engine, or retry from the failed-connection screen.
- Help, the initialization warning, failure-screen hints, and README controls now show the same shortcuts.

In the Stats page, `r` still refreshes statistics as documented for that page. The native backend is unchanged from 0.2.6-rc.2; all automatic playback-recovery fixes remain included.

## Validation

The repeat-key regression failed with the old uppercase reload binding, and the F5 regression failed before the new shortcut was implemented. Both pass with the correction. The full frontend Go tests and vet pass, including help layout and existing reload/initialization tests updated to F5.

The inherited playback backend passed 57 Rust checks, actual muted Apple Music recovery after a dropped CDN download, paused seek/reload, and the near-end transition to the next queued song. See [verification](https://github.com/trashpenguin/pomme-tui/blob/v0.2.6-rc.3/VERIFICATION.md).

Physical USB/Bluetooth reconnection, default-device switching, clean Windows user/VM testing, and Rust advisory review remain outstanding. This is an unsigned Windows x64 **prerelease**.

## Update

Quit Pomme, extract `pomme-tui-0.2.6-rc.3-windows-x64.zip` into a new folder, and start `Pomme.exe`. The normal Pomme profile is retained. `pomme version` should report `0.2.6-rc.3`.

Attach or redistribute these matching files together:

- `pomme-tui-0.2.6-rc.3-windows-x64.zip`
- `pomme-tui-0.2.6-rc.3-source.zip`
- `SHA256SUMS-0.2.6-rc.3.txt`

Requirements remain Windows 10/11 x64, an active Apple Music subscription, installed Chrome x64 Widevine, Microsoft Visual C++ x64 Runtime, and WebView2. Widevine is not included. No offline downloads, lossless playback, or seamless gapless playback is claimed.
